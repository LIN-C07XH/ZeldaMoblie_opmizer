# 存档

[English](saves.md) | **简体中文**

## 存档位置

活动存档目录是项目内的 `work/save/`，不在应用包里。目录结构与游戏在主机上的存档数据相同（`slot_00/` … `slot_05/`、`option.sav`、相册、图鉴和 `storage/`）。

游戏挂载存档时，宿主会把它克隆为 `work/save.work/`。游戏每次提交时，完整的工作副本通过 APFS 克隆和目录交换发布回 `work/save/`，因此 `work/save/` 始终是完整、一致的快照。崩溃后残留的未提交工作副本会在下次挂载时丢弃。写入方持有排他锁 `work/save.lock`。实现位于 `host/filesystem.c`。

> [!WARNING]
> 游戏运行时对 `work/save/` 的修改**不会**被合并，会被游戏下一次提交覆盖。复制、导入或编辑存档前请先退出游戏，也不要让同步软件管理这个目录。

## 备份

退出游戏后复制整个目录，例如：

```sh
mkdir -p work/save-backups
cp -Rc work/save "work/save-backups/$(date +%Y%m%d-%H%M%S)"
```

`cp -c` 会建立 APFS 克隆，瞬间完成，在文件变化前不额外占用空间。

## 从主机导入存档

1. 用存档管理工具从你自己的主机导出《王国之泪》的存档数据。
2. 退出游戏，按上面的方法备份 `work/save/`。
3. 原始导出保持不动，例如放在 `local/save-imports/`（已被 Git 忽略）。
4. 用导出存档目录的副本替换 `work/save/` 的内容。

较早游戏版本的存档可以在 v1.4.3 中读取，游戏会自行升级。如果只替换某个 `progress.sav`，对应的说明文字和缩略图仍是旧的，存档列表可能显示错误的地名，直到游戏再次保存。

## iPhone / iPad

`./script/ios.sh transfer seed` 会把 Mac 上的存档复制到设备一次。如果设备上已有内容不同的存档，传输会拒绝覆盖。之后需要下面的云存档功能才能在设备之间同步。

## Mac 与 iPhone / iPad 云存档

Mac 的菜单栏 **Zelda-Mobile → 云存档 → 关联云存档文件夹…** 与手机启动页的 **Link Cloud Folder** 应选择同一个云盘目录，例如 iCloud Drive 中新建的独立文件夹。不要选择活动的 `work/save/` 或包含它的目录。系统文件夹选择器授权访问并保存书签，无需 CloudKit 容器或额外账号凭据。

Mac 启动前最多等待 5 秒下载，可以在云存档菜单中取消；失败或超时后使用本地存档。游戏运行中不下载，以免覆盖已挂载的工作副本。切换到其他应用、点击“上传已保存进度”或正常退出时，上传游戏最后一次提交的完整快照。退出最多等待 5 秒，未完成时保留本地存档；强制退出不保证上传。手机在切到后台时上传。

两端使用相同的 A/B 快照、内容哈希及元数据协议。只有完整校验后的快照才会替换本地存档，旧本地版本保存在 `work/cloud-save-backups/`。首次关联时两边已有不同存档，或两边都发生修改，会保留双方并报告冲突；退出游戏、备份两边后再处理。取消关联不会删除云端存档。

请先在游戏里保存，再等待云盘完成网络同步后切换设备，避免同时游玩。菜单里的“已同步”表示已提交到本机文件提供程序，不代表远端设备已经下载完成。
